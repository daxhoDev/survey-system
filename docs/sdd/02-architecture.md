# 02 — Architecture

[← Back to index](MAIN.md)

## 1. Monorepo

pnpm workspace (`pnpm-workspace.yaml`: `apps/*`, `packages/*`). Root
`package.json` pins pnpm `11.5.3` through `devEngines`.

| Package | Path | Role |
|---------|------|------|
| `@survey-system/api` | `apps/api` | REST API — Express 5 + TypeScript, Prisma 7 (PostgreSQL) |
| `@survey-system/web` | `apps/web` | Web app — Vite + React 19 + Tailwind 4 + shadcn/ui |
| `@survey-system/schemas` | `packages/schemas` | Shared Zod 4 schemas (validation + OpenAPI metadata), consumed as TypeScript source |

- **ARCH-01** `[implemented]` All dependencies are managed with `pnpm`, from the root or the relevant workspace.
- **ARCH-02** `[implemented]` Request/response shapes shared by API and web are defined once, in `packages/schemas`, and imported as `@survey-system/schemas`.
- **ARCH-03** `[implemented]` Zod schemas are the single source for validation **and** OpenAPI documentation (via `@asteasolutions/zod-to-openapi`). `extendZodWithOpenApi(z)` runs in `packages/schemas/src/zod-setup.ts` and `apps/api/src/lib/zod-setup.ts` (imported first in `server.ts`).

## 2. Backend layers (`apps/api/src`)

```
routes/        Express routers: wire middlewares + controller methods, instantiate dependencies
controllers/   HTTP concerns: read req, call service, shape response envelope, set cookies
services/      Business rules and validation (Zod safeParse + domain checks), throw AppError
repositories/  Data access with Prisma; map snake_case DB rows ⇄ camelCase domain objects
middlewares/   auth, error, logging, request context
lib/           prisma client, openapi registry/generator, zod setup
config/        pino logger
context/       AsyncLocalStorage request context (per-request child logger)
utils/         AppError, rate limiter factory, BigInt-safe JSON serializer
types.ts       Domain types (inferred from Zod) and repository/service interfaces
generated/     Prisma client — GENERATED, never edit
```

- **ARCH-04** `[implemented]` Layering is strict: routes → controllers → services → repositories → Prisma. Controllers never touch Prisma; repositories contain no business rules.
- **ARCH-05** `[implemented]` Dependencies are injected via constructors (`new SurveyService(new SurveyRepository())`), wired in the router modules. Services and repositories implement the interfaces in `types.ts` (`ISurveyService`, `IAnswerRepository`, …).
- **ARCH-06** `[implemented]` Repositories return camelCase domain objects (`Survey`, `Answer`, `User`, `RefreshToken`); snake_case column names never leak above the repository layer.
- **ARCH-07** `[implemented]` Domain types are derived from the shared Zod schemas with `z.infer` (`CreateSurveyData`, `Question`, `CreateAnswerData`, …).
- **ARCH-08** `[implemented]` `apps/api/src/generated/prisma` is generated by `prisma generate` and must never be edited manually.
- **ARCH-09** `[implemented]` Controllers are bound with `.bind(controller)` when registered on a router. Express 5 forwards errors thrown in async handlers to the error middleware, so handlers do not need try/catch.

## 3. Request pipeline (`apps/api/src/app.ts`)

Order is normative:

1. `loggingMiddleware` — pino-http; assigns `req.id` (UUID v4), redacts cookies.
2. `requestContextMiddleware` — runs the rest of the request inside `AsyncLocalStorage` with a child logger carrying `requestId`.
3. `express.json()`.
4. `cookieParser()`.
5. `cors({ credentials: true, origin })` — origin from configuration (see [05-configuration.md](05-configuration.md), CFG-06).
6. `helmet()`.
7. Global rate limiter on `/api/` (see [04-api-conventions.md](04-api-conventions.md)).
8. Routers:
   - `/api/v1/surveys` → `surveyRouter` (nests `answerRouter` at `/:slug/answers` with `mergeParams`).
   - `/api/v1/users` → auth rate limiter + `userRouter`.
9. `/api/v1/docs` (Swagger UI) and `/api/v1/docs-raw` (OpenAPI JSON).
10. Catch-all `app.all("/*splat")` → `AppError` 404.
11. `ErrorMiddleware.handleGlobalError`.

- **ARCH-10** `[implemented]` `AuthMiddleware.protect` and `AuthMiddleware.optionalAuth` (when a session is present) add `userId` to the request-scoped logger after authenticating (see [10-auth.md](10-auth.md)).
- **ARCH-11** `[implemented]` Code obtains the logger with `getLogger()` (`context/requestContext.ts`) so every log line carries `requestId` (and `userId` when authenticated).

## 4. Frontend

See [20-frontend.md](20-frontend.md). The web app talks to the API only through
the Orval-generated React Query client in `apps/web/src/lib/api`, which is
generated from the API's OpenAPI document (`/api/v1/docs-raw`).

## 5. Contract flow

```
packages/schemas (Zod) ──► apps/api validation (services/controllers)
          │
          └──► apps/api/src/lib/openapi.ts (registry) ──► GET /api/v1/docs-raw
                                                            │
                                                            ▼ orval (root: pnpm generate:api)
                                                apps/web/src/lib/api (generated hooks + types)
```

- **ARCH-12** `[pending: BL-01]` The OpenAPI document must describe the real responses (envelope, status codes, server URL). Until BL-01 is done, the generated web client types may not match the actual payloads and the web code casts responses (`as any`, `as unknown as`).
